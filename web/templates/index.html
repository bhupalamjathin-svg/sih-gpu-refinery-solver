📐 Mathematical Foundations & Algorithm Derivations

Rigorous first-order saddle-point theory engineered for massive data parallelism.

1. Saddle-Point Minimax Formulation
Every constrained linear program is recast into an unconstrained saddle-point minimax problem:
min_{x ∈ [l, u]} max_{y ≥ 0}   L(x, y) = cᵀx + yᵀ(Ax − b)
Subject to: x_j ∈ [l_j, u_j],   y_i ≥ 0 for inequalities
Saddle-point (x*, y*) satisfies the Karush-Kuhn-Tucker (KKT) optimality conditions: primal feasibility, dual feasibility, and complementary slackness y*(Ax* - b) = 0.
2. Chambolle-Pock Proximal Updates
Alternating gradient ascent on dual variable y and descent on primal variable x with over-relaxation:
y^{k+1} = proj_{Y}( y^k + σ ( A x̄^k − b ) )
x^{k+1} = proj_{[l,u]}( x^k − τ ( c + Aᵀ y^{k+1} ) )
x̄^{k+1} = x^{k+1} + θ ( x^{k+1} − x^k ),   θ = 1.0
Note that dual update uses over-relaxed primal point x̄^k. Projection onto simple box constraints [l, u] is O(N) elementwise clipping, perfectly parallelized on CUDA.
3. Ruiz Diagonal Equi-Scaling
Condition number κ(A) determines the spectral radius and convergence speed. Ruiz equilibration computes:
d_i = 1 / sqrt( ‖A_{i,:}‖_∞ ),   e_j = 1 / sqrt( ‖A_{:,j}‖_∞ )
D = diag(d),   E = diag(e)
A ← D · A · E,   b ← D · b,   c ← E · c
After 10-15 iterations, every row and column of A has infinity norm within [1-ε, 1+ε]. Upon convergence, solutions are recovered via x = E · x_scaled and y = D · y_scaled.
4. Economic Shadow Price & Debottlenecking
Dual multipliers y*_i correspond directly to the marginal economic sensitivity:
λ_i = ∂(Operating Margin) / ∂(b_i)
If unit capacity b_i increases by 1 barrel/day:
ΔProfit = λ_i · Δb_i   ($/bbl or $/RON-bbl)
Constraints with λ_i > 0 indicate binding physical bottlenecks. Zero shadow prices indicate slack equipment with underutilized capacity.

🖥️ Hardware VRAM Architecture & Massive Problem Scaling

Sparse matrix representations shatter the memory wall of traditional CPU interior point solvers.

Traditional Dense Solvers (Cholesky Bottleneck)
Dense simplex or interior-point solvers require storing and factorizing dense matrices:
Memory = M × N × 8 bytes (Float64)
100,000 variables × 50,000 constraints = 40.0 GB RAM
Result: Out of Memory (OOM) on standard workstation GPUs.
Our Sparse CSR CUDA Architecture
Industrial LP matrices are typically > 99.5% sparse. Storing only non-zero entries (NNZ):
Memory = (2 × NNZ + M) × 8 bytes
Same 100,000 × 50,000 problem (0.1% density = 5M NNZ):
5,000,000 × 16 bytes ≈ 80 MB VRAM (500x memory saving!)
Maximum capacity on 8GB RTX 4070: 364 Million Non-Zeros.
